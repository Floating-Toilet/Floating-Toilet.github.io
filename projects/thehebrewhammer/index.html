The Hebrew Hammer

A Minecraft Server


Overview

My goal was to deploy a stable, secure multiplayer Minecraft server whilst gaining hands on experience with the Linux command line and Networking.

Technical Focus

Linux · Networking · Server Administration · Minecraft

Hardware / Enviroment

  • Hardware: Old Random Desktop and later on, a HP DL360 G6 server
  • OS: Ubuntu Server
  • Software: Java · Fabric Mod Loader · Playit.gg
  • Network: Portforwarding · Firewalls

What I built / The Story

Me and a friend had a wonderful idea of setting up a Minecraft server at Auburn as an "extra credit project" (Our instructor encouraged the class to do something in the lab to get hands on experience with the skills learned in class)

The first computer was a spare and mostly gutted out pc (Seen above), where missing parts were found in PCs that were in similar states.

After the usual first boot into BIOS making any necessary configurations then flashing the drive with Ubuntu Server OS and setup, the server was ready.

In order to figure out what type of Minecraft (Vanilla, Modded, or Purely server side plugins) we needed to install we asked the playerbase and they came back with various answers, but the largest deciding factor was that over half the player base plays on Bedrock Console edition leaving us to stay Vanilla or have server side plugins that still work with Bedrock

After some research we landed with Fabric mod loader, with the following mods:

  • Fabric API
  • FerriteCore
  • Lithium
  • Krypton
  • Clumps
  • Concurrent Chunk Management Engine
  • Packet Fixer
  • Terralith
  • Lithostitched
  • Chunky
  • Geyser
  • Floodgate

After testing connections from Java and Bedrock edition on the internal network we had to set up port forwarding—Our lab network is behind double NAT, this is important—While we had access to the lab's router we didn't have access to the main true edge router of the school

We asked our instructor to go ask tech if they could port forward on their end but even after they said it was done it still didn't work. Leading us to figure out a different way to access the server on an external network, (To this day I still don't remember how I realized the solution) I had suggested using a proxy server. Initally I looked at Cloudflare tunnels however I somehow couldn't figure out how to set it up, leading me to playit.gg concluding the issue of being unable to access the server outside the internal network.

At some point we had moved our infrastructure to a HP DL360 G6 server, mostly because we wanted to see if anything was different in a regular desktop vs a server.

Challenges & Troubleshooting

The desktop computer we had started with was gutted out and missing parts, our solution was to use the other gutted out desktops.

We did not know the needs of the users, our solution was to ask them.

We were unable to access the server on a external network despite having portforwarding done, our solution was to use a proxy server.

What I learned

I had learned how to ask users of their needs, the purposes of a proxy server, and how to use limited resources in an efficient manner.
